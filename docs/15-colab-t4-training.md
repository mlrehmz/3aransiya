# Restartable Colab T4 training

Open [the pilot notebook](../notebooks/colab_t4_pilot.ipynb) in Colab. Put the verified `data/doda-word-pairs-v1.json` artifact in `MyDrive/3aransiya/` in your own Drive. This file is generated by the [word-pair extractor](03-training-alignment-pilot.md#first-extractor-results) and contains train and validation pairs. The notebook embeds the project source, so no repository upload is needed. Confirm your intended cloud use of DODa before copying the artifact.

Select a T4 GPU and run all cells. The notebook defaults to two epochs for both candidates with batch size 128 and seed 42. It uses the installed CUDA-enabled PyTorch and requires a T4. It prints the runtime versions and uses one visible GPU. Model training on Colab remains unverified until a live run. [Colab FAQ](https://research.google.com/colaboratory/faq.html)

## Rerun after a disconnect

- Select the same runtime, mount Drive, and rerun with the same run name and training settings. Use one session per run directory. The trainer refuses to resume if the embedded code, verified data, Python version, PyTorch version, GPU type, or training schedule differs.
- The notebook verifies the prepared inputs and caches them on the local VM. A fresh VM recopies the artifact from Drive. No corpus alignment or dataframe preparation runs during training.
- The default writes a checkpoint after each optimizer step. Each checkpoint includes model and optimizer state, CPU and CUDA random state, and the next batch position. The same seed and epoch recreate the batch order. A rerun skips updates committed in the newest valid checkpoint.
- Two alternating, checksummed slots protect against an incomplete newest write. Falling back to the older slot can replay updates after that slot. An abrupt disconnect can also lose a write that Drive has yet to synchronize. Increase `SAVE_EVERY` if Drive I/O dominates, accepting a larger replay window. Set `STEPS_THIS_SESSION` to stop at a saved point after a bounded number of additional steps. [Colab Drive I/O guidance](https://research.google.com/colaboratory/faq.html)
- A completed candidate skips training on rerun. Its run directory contains the validation report and a versioned bundle with the manifest and CPU weights. Export compares the loaded bundle's greedy output with the final model on a fixed CPU fixture. The [GTK launch command](14-inference-bundle-spec.md#gtk-bundle-launch) accepts the downloaded directory.

## Verification

For both candidates, synthetic CPU training resumed mid-epoch and reached the same parameter tensors as an uninterrupted run. Corrupting the newest checkpoint recovered the previous one. Rerunning after completion preserved the checkpoint digest. The notebook's Python cells compiled, and its eight embedded sources matched the repository byte for byte. No Colab job was launched here, so GPU throughput, Drive sync behavior, and trained-bundle quality remain unmeasured.

Regenerate the notebook after changing embedded sources with `python notebooks/build_colab_notebook.py`.
