# Restartable Colab T4 training

Open [the pilot notebook](../notebooks/colab_t4_pilot.ipynb) in Colab. Upload the verified `data/doda-word-pairs-v1.json` artifact through Colab’s Files panel so it appears at `/content/doda-word-pairs-v1.json`. This file is generated by the [word-pair extractor](03-training-alignment-pilot.md#first-extractor-results) and contains train and validation pairs. The notebook embeds the project source, so no repository upload is needed. Confirm your intended cloud use of DODa before uploading the artifact.

Select a T4 GPU and run all cells. The notebook defaults to six epochs for both candidates with batch size 128 and seed 42. It uses the installed CUDA-enabled PyTorch and requires a T4. It prints the runtime versions and uses one visible GPU. Model training on Colab remains unverified until a live run. [Colab FAQ](https://research.google.com/colaboratory/faq.html)

## Rerun after a disconnect

- Rerun with the same run name and training settings. Use one session per run directory. The trainer refuses to resume if the embedded code, verified data, Python version, PyTorch version, GPU type, or training schedule differs.
- The notebook reads and verifies the prepared file directly from `/content`. No corpus alignment or dataframe preparation runs during training.
- The default writes a checkpoint after each optimizer step. Each checkpoint includes model and optimizer state, CPU and CUDA random state, and the next batch position. The same seed and epoch recreate the batch order. A rerun skips updates committed in the newest valid checkpoint.
- Two alternating, checksummed slots protect against an incomplete newest write. Falling back to the older slot can replay updates after that slot. A full runtime reset removes the local checkpoint slots. Download `/content/outputs/` to keep progress, then restore it to the same path after uploading the dataset to a fresh VM. Set `STEPS_THIS_SESSION` to stop at a saved point after a bounded number of additional steps.
- The current default run name is `t4-comparison-6epoch-v1`. It preserves the original two-epoch pilot under `t4-pilot-v1`. A completed candidate skips training on rerun. Its run directory under `/content/outputs/<run name>/<architecture>/` contains the validation report and a versioned bundle with the manifest and CPU weights. Export compares the loaded bundle's greedy output with the final model on a fixed CPU fixture. The [GTK launch command](14-inference-bundle-spec.md#gtk-bundle-launch) accepts the downloaded directory.

## Validation and tests in the notebook

The notebook runs synthetic checkpoint-recovery and bundle tests before corpus training. Set `RUN_SYNTHETIC_TESTS=False` to skip those checks on a subsequent session. After every epoch, the trainer saves a checkpoint and writes a digest-linked `validation-epoch-NNN.json` report before starting the next epoch. If interrupted during validation, it finishes that report after resuming from the epoch checkpoint. The validation cell displays strict and variant-aware scores, occurrence counts, distinct forms, and missing outputs for common, overall, and unseen words. Partial runs show any completed epoch scores. The final bundle smoke test runs once final validation is available.

The export test matches each bundle to its validation checkpoint, starts the same prediction helper used on Fedora, and checks that a rejected overlength request leaves the helper available. The locked release test remains reserved for final evaluation of the selected candidate.

## Verification

For both candidates, synthetic CPU training resumed mid-epoch and reached the same parameter tensors as an uninterrupted run. Corrupting the newest checkpoint recovered the previous one. Rerunning after completion preserved the checkpoint digest. A fault injected after the epoch checkpoint verified that resume retries validation against the same checkpoint before the next epoch. The notebook's Python cells compiled, and its embedded sources matched the repository byte for byte. No Colab job was launched here, so GPU throughput and trained-bundle quality remain unmeasured.

Regenerate the notebook after changing embedded sources with `python notebooks/build_colab_notebook.py`.

Compare the learning curves for common, overall, and unseen forms before choosing a model. The final exported bundle uses the last epoch, so inspect the curves before treating it as the release candidate.
